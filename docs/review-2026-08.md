# UI/UX & Logic Review — 2026-08-13

Findings from the full in-app audit (every view, button, keyboard shortcut, and
edge case, driven against the real app). Items are either **fixed** or listed
as recommendations with a rationale.

## Fixed during the audit

1. **Diff hunk headers showed a placeholder** (`@@ hunk @@`). Now render the
   real ranges (`@@ -12,5 +12,7 @@`).
2. **Binary file diffs leaked through as text**: the "Binary files …" marker
   sits after the diff headers, so the engine's prefix check missed it and the
   UI rendered an empty text toolbar. Fixed in both diff paths + a DiffView
   guard, with an engine test pinning `file_diff → binary, patch=None`.
3. **Unhandled clipboard rejection** when copying a SHA in an unfocused
   webview. All copies now go through a never-throwing helper with a fallback.
4. **Unhandled prefetch/search rejections** during repository transitions —
   fire-and-forget promises now swallow expected failures.
5. **Zoomed timelines had no pan** — wheel now zooms around the cursor,
   Shift+wheel pans, and scroll clamps to content (with layout tests).
6. **Evolution view had no container when empty** (inconsistent DOM shape).
7. *(Earlier this session, also audit-driven)*: camelCase IPC contract on all
   22 domain types + wire-contract tests; empty-replay explanation; error
   boundary; "entire repository" root resolution; single-branch default mode.

## Implemented recommendations

- `]` / `[` step through the current commit's changed files.
- Search results show the match kind (message / path / content).
- The playing commit's subject shows next to the transport position.
- Welcome-screen usage hint; visible `:focus-visible` focus rings.

## Logic review — sound

- **Frame math** (base + commits + working tree), index clamping, playback
  boundaries: unit-tested and re-verified in the live app (keyboard + transport
  steps).
- **Merge semantics**: first-parent default with explicit parent switching;
  verified on a real merge commit (changed-file list differs per parent).
- **Rename display**: `old → new` rows and continuity verified on the demo
  fixture's rename commit.
- **Virtualization**: a 1200-line generated diff renders ~50 DOM rows with the
  full scroll height — the large-repo invariant holds.
- **Working-tree frame**: modified + untracked files appear in both Step and
  Snapshot; index content for tracked files; synthesized patches for untracked.
- **Repo-change detection**: committing during a session raises the banner;
  refresh clears it and recomputes the working-tree frame.
- **Error paths**: PR mode without a GitHub remote fails with a clear message
  and no crash; empty ranges explain themselves.

## UI/UX recommendations (ordered by impact)

1. **First-run guidance (high)** — the Welcome screen says what the product is
   but not what to click. Add a one-line hint ("open any repository — your own
   or the demo") and optionally a "create demo repository" button that runs the
   fixture script through the engine. Biggest onboarding win available.
2. **Diff: jump between files (high)** — the Step view has no way to move to
   the next changed file from the keyboard. Bind `]`/`[` to next/previous
   changed file (and file-evolution entries in the Evolution view). Matches the
   keyboard-first philosophy.
3. **Timeline: seek precision (medium)** — drag-scrubbing on a fit-to-width
   timeline of 500+ commits is ~2px per commit. Add Ctrl+click or a dedicated
   scrub modifier that temporarily magnifies the hovered region, or zoom-to-
   cursor on wheel. Wheel-zoom currently zooms around the center, not the
   cursor — fix that regardless.
4. **Snapshot: file-tree context (medium)** — after stepping commits, the tree
   keeps selection but scrolled state can jump. Persist and restore the tree's
   scroll position per frame, like the diff scroll preservation.
5. **Search: show match kind (medium)** — results don't say whether a hit came
   from the message, a path, or pickaxe. A small badge would make results
   scannable.
6. **Playback: progress awareness (medium)** — while playing, show the
   commit's subject next to the play button (subtle, single line). Watching a
   replay should feel like reading a changelog, not a slideshow.
7. **Palette: recent commands (low)** — no memory of the last used commands;
   a "recent" section is cheap and idiomatic.
8. **Settings: per-repo defaults (low)** — defaults are global; a "hide
   generated" toggle is often repo-specific. Defer until demand.
9. **Empty states (low)** — a few remain bare text ("Select a file to see its
   changes"). Add the file-count context or an icon. Cosmetic.
10. **Accessibility (ongoing)** — buttons carry titles/aria; add visible focus
    rings for keyboard-only use (`:focus-visible` styles) and make the timeline
    playhead focusable (tab) with arrow support for screen-reader parity.

## Logic follow-ups

- **Copies in evolution** — `--follow` doesn't follow copies; a copied file's
  history starts at the copy commit. Documented limitation; revisit only if
  requested.
- **Change map caps** (500 commits / 150 files) are surfaced in the header but
  could offer a "load more" action instead of a hard stop.
- **Search pickaxe threshold** (≥3 chars) is a heuristic; consider `--pickaxe-regex`
  for short but symbol-like queries (e.g. `+x`).

## Verification

The audit runs as the in-app self-test (`VITE_SELFTEST=1 npm run tauri dev`, or
the dev-only button on the welcome screen): 25+ steps across two repositories,
including real clicks, keyboard events, and the repository-change flow. See
`src/lib/selfTest.ts`.
